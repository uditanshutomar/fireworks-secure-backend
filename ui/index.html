Can a small open model write backends that work and survive real attacks?

We gave each model an API spec. BaxBench ran the app in Docker, ran its functional tests, then fired expert-written exploits at it. An app counts as a secure pass only if every test passes and no exploit gets in.

Why it matters: in the BaxBench paper (Vero et al., 2025, arXiv:2502.11844) the best model wrote correct code only 62% of the time, and about half of the correct programs could be exploited. Working code is not the same as safe code.

1 · The experiment in one picture

Two changes to one small model, tested alone and together. Across: one shot vs a repair loop that tells the model which tests failed and which attacks worked, up to 3 retries. Down: the base model vs our fine-tuned version. Each box is the share of apps that passed every test and survived every exploit.

2 · What happens to 100 apps

Every app ends in one of three places. Broken: a functional test failed. Works, but exploited: all tests pass, yet an attack gets in, which is the dangerous case because it looks fine in a demo. Secure: works and no attack gets in. Read each bar left to right.

3 · Lift over the baseline, with uncertainty

The baseline is the small model as it ships: base Nemotron Nano 3, one shot. Each row is how many percentage points more apps are secure than the baseline. The bar is a 95% confidence interval: if it crosses zero, the gain could be noise.

4 · What a secure app costs

Cost per secure app is everything spent (all model calls, repair rounds included) divided by the number of secure apps. Up and to the left is better: more secure for less money.

5 · Which attacks still work

Each row is a kind of weakness (its CWE number). Each cell counts runs whose final app was broken into that way. Darker means more often. A dot means never.

Definitions

Secure pass: every BaxBench functional test passed and no BaxBench exploit succeeded. Cost: Fireworks list price × tokens over every model call in a run, repair rounds included; the tuned model is priced like its base model. Latency: model time only, not Docker.

How to read the uncertainty

Intervals are 95% Wilson intervals; differences use Newcombe's method. They treat every run as independent. Each scenario is run several times, so runs of one scenario are correlated and the true intervals are somewhat wider.

Built with
